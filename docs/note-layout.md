# Note 网页统一格式

所有 note 共用 `site/assets/css/note.css` 和 `site/assets/js/note.js`。网页只保存正文、公式、编号和目录等内容，通用外观与交互集中维护。

## 此前为何不统一

- 每篇页面都保留了数 KB 至十余 KB 的旧内联 CSS，再叠加公共样式和局部补丁。引用了公共 CSS，并不代表最终显示由它决定。
- 页面专用选择器优先级更高。例如两篇 divisorial note 在手机上仍使用 16px 字体、1.7 行高，其他页面是 17px、1.85 行高；导航高度也因此约为 82px 和 56px。
- 负性引理保留了专用绿色主题及横向内边距覆写，正文内边距变成 0，而其他页面是 48px。同类定理环境使用 `.proposition`、`.note-statement` 等不同包装，需要在公共样式中统一适配。
- 导航、返回顶部按钮和资源引用随不同模板复制，没有同时更新所有页面。局部修改解决了一篇 note 的问题，却留下了其他页面的旧版本。

## 后续维护规则

1. 新 note 复用现有页面外壳，只替换正文片段；从 TeX 转换时不重生成已发布页面的导航、目录或公共样式。
2. 通用布局、字体、颜色、定理块、证明和折叠交互只改共享 CSS/JS。不要在页面 head 新增样式块或复制旧的手机补丁；正文图形中必要的 SVG 样式不受此限制。
3. CSS 按 KaTeX、`note.css` 的顺序加载；KaTeX JS 在 `note.js` 之前加载。`note.css` 和 `note.js` 的 `v` 参数分别取文件 SHA-256 的前 12 位，各篇同步使用。彩蛋脚本保留，导航和返回顶部控件使用同一外壳。
4. 保留数学正文、公式 annotation、编号、旧锚点和完整证明。长证明保留“概览＋折叠完整证明”，短证明直接显示；不要为了视觉统一改变论证结构。

有目录的长 note 和没有目录的短 note 可以共存。当前 8 页有目录，负性引理、Uniform Domination 和 Valuative Decay 这 3 篇短 note 没有目录，这是合理的内容差异；版心、字体和组件样式应保持一致。

## 发布前检查

在仓库根目录运行：

```text
python tools/sync-note-shell.py
python tools/check-note-layout.py
```

需要机器可读结果时加 `--json`。检查涵盖共享资源及其版本、head 内无样式块、单一 h1、一致的导航和脚本引用、一个返回顶部控件，以及本地显示资源是否存在。它不改写正文，也不检查旧的数学超链接。

GitHub Actions 会在构建前运行同一检查；若新增页面绕过共享模板或资源版本未同步，构建会停止并列出问题。

修改公共样式后，还需检查全部受影响 note 的桌面与手机页面，特别是定理块、折叠证明、目录和长公式的局部滚动；发布后核对线上版本。结构检查通过不能代替视觉检查或数学核验。
